Every cheatsheet entry has two key parts that mirror how people actually look up information.

## Anchor and Content

- **anchor** — The retrieval cue. What you scan for. (command, shortcut, keyword)
- **content** — The information you need when you find it. (description, action, result)

Think of it like a dictionary: you scan for the word (anchor) to find its definition (content).

```json title="Basic entry"
{
  "anchor": "git status",
  "content": "Show staged, unstaged, and untracked files."
}
```

## Optional Fields

Entries can include additional optional fields for deeper information.

### Details

When a brief `content` isn't enough, use `details` for extended explanation. `details` is always markdown (GitHub-Flavored Markdown in `@chson/ui`).

```json title="Entry with details"
{
  "anchor": "git rebase -i",
  "content": "Interactive rebase for editing commit history.",
  "details": "Opens an editor with a list of commits. You can:\n- `pick` to keep a commit\n- `squash` to combine with previous\n- `reword` to change the message\n- `drop` to remove entirely"
}
```

**How renderers show it** depends on `documentType`:

| Document type | Typical treatment of `details` |
| ------------- | ------------------------------ |
| cheatsheet | Behind a single **More** control (popover in `@chson/ui`) |
| checklist, runbook, tldr | Progressive disclosure (collapsed until expanded) |
| **bookmarks** | **Always visible** on the card — this is the link blurb, not a “More” panel |

Bookmarks are the intentional exception: `content` holds the URL, so `details` is the description users should read without an extra click. See [Use Cases](/docs/use-cases#bookmarks) and [Rendering Tips](/docs/rendering-tips).

### URL

Link to external documentation or resources with the `url` field. (For bookmarks, the destination URL lives in **`content`**, not `url`.)

```json title="Entry with url"
{
  "anchor": "git bisect",
  "content": "Binary search to find the commit that introduced a bug.",
  "url": "https://git-scm.com/docs/git-bisect"
}
```

Both fields can be combined when appropriate. Put warnings and caveats in `content`
(if brief) or `details` (if they need more room).

## Sections

Entries are organized into sections, each with a title and optional description. Sections group related entries logically—by functionality, context, or workflow.

```json title="Section structure"
{
  "sections": [
    {
      "title": "Navigation",
      "description": "Moving around the interface.",
      "entries": [
        { "anchor": "ctrl + n", "content": "Next item" },
        { "anchor": "ctrl + p", "content": "Previous item" }
      ]
    }
  ]
}
```
